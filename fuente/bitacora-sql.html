Bases de datos · SQL

Bitácora SQL

LDD para construir la base, LMD para llenarla y consultarla. Cada bloque de código de esta bitácora es una base SQLite real que corre en tu navegador: edítalo, ejecútalo con Ctrl/⌘ + Enter y equivócate sin miedo, porque cada ejecución arranca con los datos limpios.

El mapa

LDD · Lenguaje de Definición de Datos

Construye y cambia la estructura: tablas, columnas, tipos, llaves y reglas.

CREATE · ALTER · DROP · TRUNCATE

Es hacer los planos y levantar los cuartos. Crear un procedimiento almacenado también es LDD.

LMD · Lenguaje de Manipulación de Datos

Trabaja con las filas: las agrega, las cambia, las borra y las consulta.

INSERT · UPDATE · DELETE · SELECT

Es meter, mover y buscar los muebles dentro de esos cuartos.

Regla rápida: si la sentencia cambia cómo es la tabla, es LDD. Si cambia o lee lo que hay dentro, es LMD.

Ruta de la sesión

  1. LDD: CREATE TABLE con todas sus restricciones, llaves compuestas, ALTER y DROP.
  2. LMD y SELECT: INSERT, UPDATE y DELETE sin romper llaves; luego SELECT de lo simple a GROUP BY, HAVING y subconsultas.

  4. Procedimientos almacenados: crear y llamar procedimientos en T-SQL con parámetros, IF, errores y transacciones.

Llave primaria compuesta

En FacturaDetalle ninguna columna sola identifica la fila: la factura 2 tiene varios productos y el producto 2 aparece en varias facturas. Lo que no se repite es la pareja (IDFactura, IDProducto). Es una entidad débil: depende de la factura.

El orden importa

  • Crear: primero las tablas que no apuntan a nadie (Categoria, Proveedor, Cliente, Empleado), al final las que tienen FK (Producto, FacturaEncabezado, FacturaDetalle). SQL Server no te deja crear una FK hacia una tabla que no existe.
  • Borrar: al revés. Primero las hijas, después las padres.
  • Tipos: la FK debe tener el mismo tipo que la PK a la que apunta. Un INT que apunta a un VARCHAR da error en SQL Server.

ALTER TABLE

Cambia una tabla que ya existe sin perder sus datos.

ALTER TABLE Entrenador ADD email VARCHAR(100);        -- agregar columna
ALTER TABLE Entrenador DROP COLUMN email;              -- quitar columna
ALTER TABLE Entrenador ALTER COLUMN nombre VARCHAR(80); -- cambiar tipo (solo SQL Server)
ALTER TABLE Factura ADD CONSTRAINT FK_Factura_Cliente   -- agregar restricción con nombre
  FOREIGN KEY (IDCliente) REFERENCES Cliente(IDCliente);

En SQL Server se escribe ADD columna sin la palabra COLUMN. SQLite no tiene ALTER COLUMN ni ADD CONSTRAINT; este simulador sí acepta ADD CONSTRAINT (FOREIGN KEY, CHECK, UNIQUE y PRIMARY KEY), así que escríbelo como en SQL Server. ALTER COLUMN sigue sin estar.

SELECT completo

SELECT [DISTINCT] columnas, expresiones, agregados AS alias
FROM tabla
  [JOIN otra ON condición]
WHERE condición sobre filas
GROUP BY columnas
HAVING condición sobre grupos
ORDER BY columnas [ASC | DESC]
LIMIT n;                 -- SQL Server: SELECT TOP n ...

El orden en que se ejecuta

FROM / JOIN→WHERE→GROUP BY→HAVING→SELECT→DISTINCT→ORDER BY→LIMIT / TOP

De ahí salen tres reglas: un alias del SELECT no existe todavía en el WHERE (sí en ORDER BY); un agregado no puede ir en WHERE porque los grupos aún no existen (va en HAVING); y WHERE quita filas antes de agrupar.

Método para cualquier pregunta

  1. ¿Qué columnas quiero ver? → SELECT
  2. ¿De qué tablas salen? Si son varias, ¿cómo se conectan? → FROM … JOIN … ON
  3. ¿Qué filas me interesan? → WHERE
  4. ¿La pregunta dice “por cada”, “cuántos”, “total”, “promedio”? → GROUP BY + agregados
  5. ¿Hay condición sobre el resultado del agregado? → HAVING
  6. ¿Orden o “los primeros n”? → ORDER BY + LIMIT/TOP

Paso 4 de la ruta

Procedimientos almacenados

Un procedimiento almacenado es código T-SQL guardado dentro de la base con un nombre. Recibe parámetros, valida reglas, hace INSERT, UPDATE, DELETE o SELECT, y se llama con EXEC. Crearlo es LDD (CREATE PROCEDURE); lo de adentro es LMD.

Para qué sirven

  • Reutilizar: “dar de alta un Pokémon” se escribe una vez y todos lo llaman igual.
  • Reglas en un solo lugar: las validaciones viven en la base, no repetidas en cada programa.
  • Seguridad: se puede dar permiso de ejecutar el procedimiento sin dar permiso directo sobre las tablas.
  • Menos tráfico: la aplicación manda una llamada corta en lugar de muchas sentencias.

Sobre el simulador. Los procedimientos son de SQL Server; SQLite no los tiene. Esta bitácora trae un intérprete de T-SQL para que los ejemplos y los ejercicios corran de verdad. Cuando tu código usa T-SQL (variables con @, EXEC, IF, PRINT…), los errores se comportan como en SQL Server; más abajo está la tabla.

Anatomía

CREATE PROCEDURE NombreDelProcedimiento
  @parametro1  TIPO,
  @parametro2  TIPO = valor_por_omision,   -- opcional al llamarlo
  @salida      TIPO OUTPUT                 -- de salida
AS
BEGIN
  SET NOCOUNT ON;      -- no mostrar "(n filas afectadas)"
  -- sentencias
END
GO                     -- aquí termina el procedimiento

EXEC NombreDelProcedimiento valor1, valor2, @variable OUTPUT;

CREATE PROCEDURE debe ser la primera sentencia de su lote, y el cuerpo llega hasta el siguiente GO. Por eso va GO antes y después. PROC abrevia PROCEDURE y EXECUTE es lo mismo que EXEC.

Parámetros de entrada

Se declaran entre el nombre y el AS, cada uno con @ y su tipo. Al llamar, se pasan por posición (en el orden en que se declararon) o por nombre (@param = valor, en cualquier orden). Un parámetro con = valor es opcional.

Trampa clásica. VARCHAR sin tamaño en un parámetro o en un DECLARE vale VARCHAR(1): 'Ash' se guarda como 'A' y el WHERE ya no encuentra nada. Escribe siempre el tamaño.

Variables y PRINT

DECLARE crea la variable, SET le pone un valor y SELECT @v = … la llena desde una consulta (si la consulta trae varias filas, se queda con la última). PRINT escribe un mensaje. Para unir texto con números se convierte con CAST y se concatena con +.

IF, ELSE y WHILE

Cada uno controla una sentencia. Si quieres varias, envuélvelas en BEGIN … END.

OUTPUT y RETURN

Un parámetro OUTPUT devuelve un valor a una variable de quien llama; la palabra OUTPUT va en el CREATE y en el EXEC. RETURN n termina el procedimiento y deja un código entero (por costumbre 0 = bien) que se recibe con EXEC @codigo = ….

Validar y avisar errores

El patrón de siempre: revisar con IF, avisar con RAISERROR('mensaje', 16, 1) y salir con RETURN. El 16 es el nivel de gravedad (de 11 a 16 son errores del usuario) y el 1 es el estado. %s y %d se reemplazan con los datos que pongas después.

Lo que pasa si olvidas el RETURN: RAISERROR avisa, pero el procedimiento sigue y hace el UPDATE con un monto negativo.

THROW número, 'mensaje', estado; es la forma moderna. A diferencia de RAISERROR, detiene el lote completo: lo que sigue en ese lote ya no corre.

Transacciones y TRY…CATCH

Una transacción agrupa varias sentencias en un “todo o nada”: BEGIN TRANSACTION, luego COMMIT para guardar o ROLLBACK para deshacer. Con BEGIN TRY … END TRY BEGIN CATCH … END CATCH, cualquier error dentro del TRY salta al CATCH, donde ERROR_MESSAGE() dice qué pasó.

Cambiar, consultar y borrar

ALTER PROCEDURE reemplaza un procedimiento que ya existe (si usas CREATE otra vez, da error porque ya existe). CREATE OR ALTER hace cualquiera de las dos. sp_helptext muestra el código guardado y DROP PROCEDURE lo elimina.

El GO olvidado

Es el error más común al practicar en SSMS: sin GO después del END, el EXEC de prueba se guarda dentro del procedimiento. Se crea, pero no corre nada. Agrega GO en la línea que sigue al END y vuelve a ejecutar.

Cómo se comportan los errores

SituaciónQué pasa en SQL Server (y aquí)
Llave repetida, FK, CHECK o NOT NULLSe cancela esa sentencia y el procedimiento sigue con la siguiente
RAISERROR con nivel 11 a 16Muestra el error y sigue. Por eso va seguido de RETURN
THROWMuestra el error y detiene el lote completo
Error de sintaxis o variable sin declararNo se ejecuta nada de ese lote
Cualquier error dentro de BEGIN TRYSalta al BEGIN CATCH

En las celdas que no usan T-SQL (las de LDD y LMD), la ejecución se detiene en el primer error para que lo veas sin ruido.

Qué entiende este simulador

Sí: CREATE, ALTER, CREATE OR ALTER y DROP PROCEDURE; parámetros con valor por omisión y OUTPUT; EXEC por posición, por nombre y con código de retorno; DECLARE, SET y SELECT @v = …; IF/ELSE, WHILE, BREAK, CONTINUE, BEGIN…END y RETURN; PRINT; RAISERROR (con %s y %d) y THROW; TRY…CATCH con ERROR_MESSAGE() y ERROR_NUMBER(); BEGIN TRAN, COMMIT y ROLLBACK; @@ROWCOUNT, @@TRANCOUNT, SCOPE_IDENTITY() y OBJECT_ID(); concatenar con +; ISNULL, CONVERT, LEFT, RIGHT, DATEDIFF, DATEADD, GETDATE; GO; sp_helptext.

No: cursores, variables de tabla, tablas temporales (#t), SQL dinámico, funciones de usuario y triggers. Y si concatenas dos columnas sin texto en medio (Nombre + ApPaterno), aquí se suman como números: pon ' ' en medio o usa CONCAT.

4. SUM() para actualizar los datos calculados

Primero cada línea: TotalLinea = Cantidad * Precio. Después el subtotal de cada factura es la suma de sus líneas, con una subconsulta correlacionada: dentro del SUM, el WHERE apunta a la factura que se está actualizando.

UPDATE FacturaEncabezado
SET Subtotal = (SELECT SUM(D.TotalLinea)
                FROM FacturaDetalle D
                WHERE D.IDFactura = FacturaEncabezado.IDFactura);

IVA (16%) y Total van en un UPDATE aparte, porque en el mismo SET verían el Subtotal viejo.
